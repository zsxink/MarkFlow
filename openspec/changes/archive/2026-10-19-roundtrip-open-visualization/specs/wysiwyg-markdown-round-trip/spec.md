# wysiwyg-markdown-round-trip Specification (delta)

## ADDED Requirements

### Requirement: 行内代码字符级往返保真

受支持语法边界 MUST 包含与其他 mark 相邻、或首尾含空格与反引号的行内代码。行内代码的可见文本、代码标记范围与反引号数量 MUST 在 Markdown → WYSIWYG → Markdown 往返后保持等价。序列化 MUST 依据代码内容选择足够长的围栏，使内容自身含反引号时不被提前闭合，并 MUST 按 CommonMark 规则处理首尾空格（内容以空格开头或结尾、或由反引号包裹时需补填充空格）。此类字符级差异 MUST NOT 被视为可接受的规范化，也 MUST NOT 单独触发整篇文档降级。

#### Scenario: 含反引号的行内代码往返
- **WHEN** 文档包含内容自身带反引号的行内代码，如 `` `` Ctrl+` `` `` 或 ``` ``a`b`` ```
- **THEN** 序列化使用比内容最长反引号串更长的围栏
- **THEN** 重新解析后代码内容与代码标记范围均与原文等价

#### Scenario: 首尾空格的行内代码往返
- **WHEN** 文档包含内容以空格开头或结尾的行内代码，如 `` `# ` ``、`` ` leading` ``、`` `  two spaces  ` ``
- **THEN** 序列化按 CommonMark 规则补足填充空格，空格 MUST 保留在代码内容内
- **THEN** 重新解析后的语义指纹与原文一致

#### Scenario: 行内代码与其他 mark 相邻往返
- **WHEN** 行内代码位于加粗、链接等其它 mark 之内或紧邻
- **THEN** 加粗、链接等外侧 mark 的边界与目标保持不变
- **THEN** 代码内容不因相邻 mark 的开关而被移动或改写

#### Scenario: 真实语料回归
- **WHEN** 对包含这类行内代码的真实文档（如 `README.en.md`）执行准入
- **THEN** 往返校验通过，文档进入可编辑 WYSIWYG

## MODIFIED Requirements

### Requirement: 允许的规范化不得改变语义
系统 MAY 对受支持 Markdown 执行显式列入兼容策略的格式规范化，但 MUST 保持语义等价；规范化不得更改文本、链接目标、图片地址、代码内容、列表序号语义、任务状态或表格单元格数据。

#### Scenario: 标记风格规范化
- **WHEN** 输入使用受支持但非首选的项目符号、强调分隔符或空白形式
- **THEN** 输出可以使用统一风格
- **THEN** 解析后的文档结构与用户内容必须等价

#### Scenario: 未登记的改写不被接受
- **WHEN** 往返结果与输入存在未列入兼容策略的结构或属性差异
- **THEN** 系统不得将该差异视为安全规范化
- **THEN** 文档进入局部字面量保留或 Source 降级流程，而非整篇降级

#### Scenario: 行内代码字符差异不属于规范化
- **WHEN** 往返结果改变了行内代码的字符（含空格或反引号）或其标记范围
- **THEN** 系统 MUST NOT 把该差异列入兼容策略或视为安全规范化
- **THEN** 该差异 MUST 通过序列化修复消除，或使对应块进入局部字面量保留

#### Scenario: 两条解析路径的默认属性表示等价
- **WHEN** 编辑器解析路径与非变异校验路径仅在缺省属性、扩展运行时默认值或 mark 集合顺序上存在差异
- **THEN** 语义指纹将缺省值与等价默认值规范化为相同表示
- **THEN** 非默认表格跨度、链接目标、图片 authored attributes 和正文 mark 范围仍保持语义敏感
