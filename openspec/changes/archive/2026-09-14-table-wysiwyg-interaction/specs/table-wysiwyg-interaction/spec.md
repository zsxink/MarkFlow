# table-wysiwyg-interaction Specification (delta)

## Purpose

定义 MarkFlow 在所见即所得（WYSIWYG）模式下创建与编辑 GFM 表格的交互契约——从 Markdown 输入自动成表、悬停工具条、单元格右键菜单、行列增删与对齐编辑，以及编辑结果无损写回 Markdown。让表格在可视化编辑器中成为一等公民，与源码模式双向保真。

## ADDED Requirements

### Requirement: Markdown 输入自动成表

在 WYSIWYG 模式下，用户输入符合 GFM 表格语法的 Markdown（表头行 + 分隔行 + 至少一行内容，如 `| a | b |` 回车 `| --- | --- |` 回车 `| 1 | 2 |`）并按下 Enter 后，系统 SHALL 将这段 Markdown 解析为一个可编辑的表格节点，光标落于首个数据单元格内。仅当输入在解析时构成完整合法表格时触发；分隔行格式错误或列数不一致的输入 MUST NOT 被自动转换（保持原输入文本）。

#### Scenario: 输入合法表格语法自动成表
- **WHEN** 用户在新行输入 `| a | b |`、换行输入 `| --- | --- |` 并回车
- **THEN** 输入被转换为可编辑表格节点，含 1 行表头 + 1 行空数据行
- **THEN** 光标位于第一行表头下方第一个数据单元格内

#### Scenario: 非法表格语法不转换
- **WHEN** 用户输入分隔行列数与表头不一致的 Markdown 表格
- **THEN** 输入保持为普通段落文本，不产生表格节点
- **THEN** 不弹错误提示，等待用户自行修正

### Requirement: 表格悬停工具条

当光标位于表格内或鼠标悬停于表格上时，系统 SHALL 在表格上方显示一个浮动工具条，提供行列结构化操作。工具条 MUST 包含：插入行（上方/下方）、插入列（左侧/右侧）、删除当前行、删除当前列。工具条在光标离开表格且无任何表格相关选区时隐藏。

#### Scenario: 表格内出现悬停工具条
- **WHEN** 用户将光标移入任意表格单元格
- **THEN** 表格上方显示浮动工具条，包含加行/加列/删行/删列按钮
- **THEN** 工具条位置随表格位置自适应，不遮挡单元格内容

#### Scenario: 悬停工具条操作生效
- **WHEN** 用户在表格内第 2 行调用「在下方插入行」
- **THEN** 表格在第 2 行下方新增一行，原有行与内容不变
- **THEN** 新行单元格数与表头列数一致

#### Scenario: 光标离开表格工具条隐藏
- **WHEN** 光标移出表格范围（表格结构与编辑命令不支持的区域）
- **THEN** 悬停工具条隐藏，不残留 DOM

### Requirement: 表格单元格右键菜单

在 WYSIWYG 模式下，用户在表格单元格内按下鼠标右键时，系统 SHALL 弹出表格专用右键菜单。菜单 MUST 包含结构化操作（上方/下方插入行、左侧/右侧插入列、删除行、删除列、删除表格）与对齐操作（左对齐/居中/右对齐）以及表头行切换。菜单 MUST 通过统一 `showContextMenuStatic` API 创建，遵循 `context-menu` 规范的 DOM 结构与定位交互。某一起作用域（当前行/列/整表）MUST 与触发位置所在单元格对应。

#### Scenario: 单元格右键出现表格菜单
- **WHEN** 用户在表格某单元格内右键
- **THEN** 弹出包含行列增删、对齐、表头切换、删除表格的专用菜单
- **THEN** 菜单定位在鼠标位置，样式与既有 context-menu 一致

#### Scenario: 右键菜单的对齐操作写入单元格
- **WHEN** 用户在表格菜单选择「居中对齐」
- **THEN** 当前单元格所在列的 Markdown 对齐标记行更新为 `:---:`
- **THEN** 当前单元格所在列的所有单元格视觉居中

#### Scenario: 右键菜单的删除行作用域正确
- **WHEN** 用户在表格第 3 行右键并选择「删除行」
- **THEN** 仅第 3 行被删除，其余行与列不受影响

### Requirement: 行列增删与对齐无损写回 Markdown

所有通过交互产生的表格编辑（增删行、增删列、对齐、表头切换）在切换回源码模式或保存时 SHALL 被序列化为合法 GFM 表格 Markdown，且满足 `wysiwyg-markdown-round-trip` 的往返保真要求。单元格内的文本、行内格式、转义竖线在编辑后 MUST 保持不变；对齐属性 MUST 通过对齐标记行（`:---` / `:---:` / `---:`）持久化。

#### Scenario: 增删列后序列化保持列数一致
- **WHEN** 用户在 3 列表格中删除中间列
- **THEN** 序列化输出为 2 列表格，所有行的单元格数与表头一致
- **THEN** 重新解析该输出仍得到等价表格

#### Scenario: 设置对齐后序列化含对齐标记
- **WHEN** 用户将某列设为右对齐并切换回源码模式
- **THEN** 源码中该列对齐标记为 `---:`，单元格数据文本不变

### Requirement: 表格编辑适配既有安全管道

表格编辑产生的文档 MUST 进入既有的 admission / eligibility / reconcile 编辑安全链路。当编辑导致文档无法安全往返（如产生散列不一致的表格）时，系统 MUST 沿用既有降级语义（文档进入源码模式），不得绕过安全门禁写入。

#### Scenario: 编辑后无法安全往返则降级源码
- **WHEN** 用户的表格编辑使文档在「解析 → 序列化 → 解析」中结构发生非规范化差异
- **THEN** 系统按既有对账流程处理，不将未登记的改写作为结果写盘
