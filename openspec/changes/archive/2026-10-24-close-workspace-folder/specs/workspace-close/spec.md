# Spec Delta

## Purpose

定义用户关闭当前已打开工作区文件夹时的行为契约：入口与启用条件、关闭后的前端状态重置、后端资源与持久化清理，以及对已打开文档的不影响保证。

## ADDED Requirements

### Requirement: 关闭工作区入口

系统 SHALL 在以下位置提供「关闭工作区」入口，且所有入口 MUST 执行同一关闭流程：

- 文件树空白区域的右键菜单（存在工作区时显示，与无工作区时「打开文件夹」入口的位置对应）；
- 原生菜单「文件 → 关闭工作区」（存在工作区时可用，无工作区时禁用）。

无工作区时文件树右键菜单 MUST NOT 显示「关闭工作区」入口。

#### Scenario: 有工作区时右键文件树空白区域

- **WHEN** 已打开工作区，用户右键点击文件树空白区域
- **THEN** 右键菜单包含「关闭工作区」项，点击后执行统一关闭流程

#### Scenario: 无工作区时右键文件树空白区域

- **WHEN** 未打开任何工作区，用户右键点击文件树区域
- **THEN** 右键菜单不包含「关闭工作区」项

#### Scenario: 原生菜单按工作区状态启用

- **WHEN** 原生菜单「文件」菜单展开
- **THEN** 已打开工作区时「关闭工作区」可用；无工作区时该项禁用

#### Scenario: 各入口执行同一关闭流程

- **WHEN** 用户从右键菜单或原生菜单任一入口触发「关闭工作区」
- **THEN** 两个入口产生相同的关闭结果（状态重置、文件树空态、后端清理）

### Requirement: 关闭后的前端状态重置

关闭工作区后，系统 MUST 将工作区路径状态置空，并将文件树 DOM 与树状态重置为初始空状态（显示「请先打开文件夹」提示）。依赖工作区路径的面板、右键菜单与原生菜单 MUST 按无工作区状态处理。

#### Scenario: 文件树回到空态提示

- **WHEN** 工作区关闭完成
- **THEN** 文件树内容清空并显示「请先打开文件夹」空态提示

#### Scenario: 右键菜单回到无工作区分支

- **WHEN** 工作区关闭后，用户右键点击文件树区域
- **THEN** 右键菜单显示「打开文件夹」「打开文件」，不显示依赖工作区的操作

### Requirement: 后端资源与持久化清理

关闭工作区时，系统 MUST 停止原工作区的文件系统监听、清除后端会话中的工作区根路径，并清除持久化设置中记录的最近工作区，使应用重启后不再自动恢复已关闭的工作区。

#### Scenario: 重启后不自动恢复

- **WHEN** 用户关闭工作区后退出并重新启动应用
- **THEN** 应用不自动恢复已关闭的工作区，文件树保持空态

#### Scenario: 关闭后不再接收原工作区变更事件

- **WHEN** 工作区关闭后，原工作区目录内的文件发生增删改
- **THEN** 文件树不因此发生任何更新

### Requirement: 已打开文档不受影响

关闭工作区 MUST NOT 关闭、丢弃或切换任何已打开的文档标签页；已打开文档的内容、脏状态、保存与另存能力 MUST 保持不变。

#### Scenario: 标签页在关闭工作区后保持可用

- **WHEN** 工作区关闭时存在已打开的文档标签页（含未保存修改）
- **THEN** 所有标签页保持打开，未保存修改保留，用户仍可继续编辑并保存到原路径
