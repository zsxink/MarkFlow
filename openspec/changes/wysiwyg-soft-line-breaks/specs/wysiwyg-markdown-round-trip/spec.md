# Spec Delta

## MODIFIED Requirements

### Requirement: 受支持 Markdown 结构往返保真
系统 MUST 对标题、段落、强调、加粗、删除线、行内代码、链接、图片、引用、分隔线、普通列表、有序列表、任务列表、围栏代码块、GFM 表格和换行语义提供双向解析与序列化。文档经过 Markdown → WYSIWYG → Markdown 往返后 MUST 保留文本内容、节点顺序、嵌套关系和用户可观察属性。

段落内的软换行（行尾无两空格、无反斜杠的单个换行符）MUST 在 WYSIWYG 中以换行呈现（渲染为独立换行元素，不依赖空白折叠），MUST 在编辑器文档模型中以显式换行节点表示（不得残留在文本节点内部），且序列化时 MUST 精确还原为裸换行符——不带尾随空格，不得静默升级为硬换行拼写（`  \n` 或 `\\\n`）。行尾两空格与反斜杠构成的硬换行 MUST 保持既有序列化输出与节点表示。软换行与硬换行的区分 MUST 在往返后保持：软换行往返后仍为软换行拼写，硬换行往返后仍为硬换行拼写。粘贴进入 WYSIWYG 的多行纯文本 MUST 应用与解析一致的软换行表示，使粘贴后的显示与解析加载相同来源的文档一致。

#### Scenario: 常用行内语法往返
- **WHEN** 文档包含嵌套的强调、加粗、删除线、行内代码，以及带标题和需转义 URL 的链接
- **THEN** 往返结果保留相同的可见文本、标记范围、链接目标和链接标题

#### Scenario: 图片属性往返
- **WHEN** 文档包含带 alt、title、本地相对路径或远程 URL 的 Markdown 图片
- **THEN** 往返结果保留图片顺序、alt、title 和可持久化源地址
- **THEN** 运行时资源 URL 不得替代原始 Markdown 地址写入结果

#### Scenario: 嵌套列表往返
- **WHEN** 文档包含多层普通列表、有序列表和任务列表，并包含跨行列表项
- **THEN** 往返结果保留列表类型、层级、条目顺序、任务勾选状态和条目正文

#### Scenario: GFM 表格往返
- **WHEN** 文档包含表头、多个数据行、空单元格、行内格式和转义竖线
- **THEN** 往返结果仍为可解析的 GFM 表格
- **THEN** 单元格数量、顺序、文本与行内格式保持不变
- **THEN** 不得退化为 HTML 表格或丢弃表格内容

#### Scenario: 多行软换行段落在 WYSIWYG 中按行显示且往返无损
- **WHEN** 源码模式输入三行无空行分隔、行尾无两空格的文本（`1 行\n2 行\n3 行`）并切换到 WYSIWYG
- **THEN** 三行在 WYSIWYG 中按三个视觉行显示（每个换行渲染为换行元素）
- **THEN** 编辑器文档模型中换行为显式换行节点，不残留在文本节点内部
- **THEN** 不编辑即保存或切回源码时，字节保持 `1 行\n2 行\n3 行`，行尾不新增空格

#### Scenario: 软换行与硬换行往返后拼写不互换
- **WHEN** 文档同时包含软换行（裸 `\n`）、两空格硬换行（`  \n`）和反斜杠硬换行（`\\\n`）
- **THEN** 软换行往返后仍为裸 `\n`，不被升级为 `  \n`
- **THEN** 硬换行往返后仍解析为硬换行，与软换行在文档模型中可区分

#### Scenario: 容器内软换行一致
- **WHEN** 列表项、引用内的段落包含软换行（如 `- 条目一\n  续行` 的懒延续）
- **THEN** WYSIWYG 中该条目按多行显示，序列化还原相同的软换行拼写

#### Scenario: 粘贴的多行纯文本显示与解析一致
- **WHEN** 用户向 WYSIWYG 段落内粘贴含单换行的多行纯文本
- **THEN** 粘贴结果按多行显示，序列化产生与解析加载相同文本一致的结果
