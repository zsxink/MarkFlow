### 3. 唯一 owner 不变量 — PASS

- 解析是 (kind, 当前 flag 态) 的纯函数，任何输入恰返回一个 owner（动态最后活跃者 → 否则静态默认；未知 kind 兜底 `source-fallback`）。flag 翻转只会改变唯一结果，不存在 undefined/双 owner 窗口（单线程 JS，无 await 穿越变更段）。
- 同 kind 重复注册：允许、last-active-wins、`conflicts` 计数 + `lastConflict{kind,supersededSource,source}` + `logWarn` 结构化 warning，从不同步吞掉；teardown 后回落到仍在册的更早 entry（有测试）。
- 抛异常路径一致性：`registerConstructOwner` 的三类校验（未知 kind / `core` / 非 `widget|source-fallback`）全部在任何 mutation 之前 throw，冲突簿记与 push 之间无可 throw 操作 → 不可能半注册（有测试：core 拒绝后 `registered=0, conflicts=0`）。
- teardown 按 entry 对象身份 splice、`tornDown` 幂等、空数组时删 key；卸载后重注册不计冲突（有测试）。

### 4. flag 失败关闭 — PASS

## 问题清单

### P2（非阻塞，建议顺手修）

1. **`renderOwnerRegistry.ts` 防御性 JS-caller 路径受 Object.prototype 原型链影响**
   - `registerConstructOwner` 用 `!(kind in DEFAULT_OWNERS)` 判未知 kind、`resolveConstructOwner` 用 `DEFAULT_OWNERS[kind] ?? 'source-fallback'` 兜底。`in` 与属性查找都会命中 `Object.prototype` 继承属性（已实证：`'toString' in Object.freeze({heading:...})` → true；`DEFAULT_OWNERS['toString']` 返回函数，非 nullish，`??` 不兜底）。
   - 后果：若 JS 调用方（绕过 TS 的 `ConstructKind` 类型）传 `'toString'/'constructor'/'valueOf'` 等名字，可注册出幽灵 kind（计入 registered/active 计数但不出现在 owners 快照），且 `resolveConstructOwner('toString')` 会返回 `{ owner: [Function], source: 'default' }` 而非按设计降级 `source-fallback`。测试的防御路径只覆盖了 `'made-up'`，未覆盖原型名。
   - 影响评估：TS 代码库内不可达（类型拦截）；无产品影响、无安全影响；仅防御声明与实现不符。
   - 建议：`Object.hasOwn(DEFAULT_OWNERS, kind)` + 兜底改 `Object.prototype.hasOwnProperty.call`（或以 `Object.create(null)` 建表），并补一条原型名测试。

### P3（备注，不要求处理）

1. `lastConflict.supersededSource` 记录的是注册序上紧邻的前一注册（即使其当前 flag 为 OFF 惰性），"superseded" 是注册序语义而非"当时实际生效者"语义——头注释规则 3 已如实声明，可接受。
2. `conflicts` 为模块级全局累计计数（非按 kind 分桶），快照仅 `lastConflict` 提供明细——与"计数器 + 最近明细"的观测设计一致，可接受。
