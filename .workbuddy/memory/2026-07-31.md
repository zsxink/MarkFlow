# 2026-07-31 — issue #246: WYSIWYG 打开 markdown 不渲染

## 根因（确认）
- 提交 M8C「收敛 M8C legacy fallback 删除 (#245)」删除了 `tiptap-markdown` 扩展与 legacy ProseMirror 的 markdown 序列化/反序列化路径。
- 默认打开链路：`store.mode='wysiwyg'` + `wysiwygEngine='legacy-prosemirror'`，且 `shouldUseCoreBackedHydration()` 旧逻辑返回 false → 走 legacy `setMarkdown(原始markdown)` → ProseMirror `setContent` → 纯文本团块（语法符号裸露、换行丢失）。
- 同时未建立 Core 会话，导致「切换到 WYSIWYG」路径也无法启用 Core-backed 渲染。
- 另一 agent 的 `docs/superpowers/plans/2026-07-31-issue-246-summary.md` 只改 `trailingNewlines` 记账，未触及根因，故「没有任何改善」。

## 修复（分支 fix/issue-246-markdown-newline-loss）
- `src/lib/editor.ts`：新增单一入口 `mountCoreBackedDocument(opened)`，打开/重载时在 feature flag 开启时一律 `openCoreSession` + 挂载 Core-backed 编辑器（WYSIWYG 走 CodeMirror + Render IR 投影；source 走纯 CodeMirror）。legacy ProseMirror 仅留空壳并隐藏。
- `hydrateCoreBackedMarkdown(opened)` 调 `mountCoreBackedDocument` 并重置 `trailingNewlines=0`，3 个调用点均加 `if (!opened) return` 守卫。
- `unmountCoreBackedDocument()` 在关闭文档时 `void closeCoreSession()` 释放会话。
- `onCoreSurfaceUpdate` 的 dirty 比较改为 `stripTrailingNewlines(normalizeImageMarkdown(doc))` 与 `lastPersistedMarkdown` 对称，避免尾部换行文件撤销后 dirty 不归零。
- `editor.stats.ts` / `outline.ts`：改为从 `getSourceView()`（CodeMirror）读取字数/大纲，避免回归为 0/空。
- `switchToSource` / `switchToWysiwyg` 加幂等 early-return。
