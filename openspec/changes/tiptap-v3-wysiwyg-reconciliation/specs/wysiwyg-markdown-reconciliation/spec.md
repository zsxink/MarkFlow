## Purpose

定义原始 Markdown、WYSIWYG 文档和序列化结果之间的安全对账协议，使不完全受支持的语法可被保留，并在无法证明安全时阻止静默覆盖。

## ADDED Requirements

### Requirement: WYSIWYG 资格门禁
系统 MUST 在加载 Markdown 到可编辑 WYSIWYG 前完成资格检查，并返回 `eligible`、`eligible-with-opaque` 或 `source-only` 结果及稳定原因。只有能够证明受支持内容可安全往返、其余内容可安全透传的文档才能进入可编辑 WYSIWYG。

#### Scenario: 完全受支持的文档
- **WHEN** 文档只包含往返规范承诺支持的语法且解析成功
- **THEN** 资格结果为 `eligible`
- **THEN** 文档可进入可编辑 WYSIWYG

#### Scenario: 可透传的不透明片段
- **WHEN** 文档包含 WYSIWYG 不原生理解但边界可确定且可原样恢复的片段
- **THEN** 资格结果为 `eligible-with-opaque`
- **THEN** 结果列出每个不透明片段的位置和类别

#### Scenario: 无法安全往返的文档
- **WHEN** 文档包含边界不确定、解析歧义、占位无法安全注入或已知不可逆的结构
- **THEN** 资格结果为 `source-only` 并包含稳定原因
- **THEN** 系统不得创建可能覆盖原文的可编辑 WYSIWYG 会话

### Requirement: 不透明片段必须可逆透传
系统 MUST 为每个不透明片段生成与用户文本不可碰撞的会话级标识，并在 WYSIWYG 表示中保留不可编辑的占位节点。序列化时 MUST 按原始顺序逐字节恢复片段，且内部 token、标识和元数据不得写入磁盘、剪贴板或导出内容。

#### Scenario: 不透明片段原样恢复
- **WHEN** 用户只编辑不透明片段之外的受支持内容
- **THEN** 序列化结果在对应位置逐字节恢复每个原始不透明片段
- **THEN** 受支持区域的编辑正常保留

#### Scenario: 多个相同片段不串位
- **WHEN** 文档包含内容相同但位置不同的多个不透明片段
- **THEN** 每个片段拥有不同的会话级标识
- **THEN** 序列化按各自原始位置和内容恢复，不得互换、合并或去重

#### Scenario: 占位完整性被破坏
- **WHEN** 占位节点被删除、复制、重复、改写或无法与登记表一一对应
- **THEN** 恢复失败并进入冲突状态
- **THEN** 系统不得输出包含内部 token 的 Markdown

### Requirement: 三方对账必须区分安全结果与冲突
系统 MUST 在模式切换和保存边界，以会话原始 Markdown、上一次已验证的 WYSIWYG 序列化基线和当前序列化候选执行对账。对账 MUST 返回 `unchanged`、`safe-edit` 或 `conflict`，并只允许前两种结果进入正常保存。

#### Scenario: 无用户编辑的等价格式差异
- **WHEN** 当前候选仅包含兼容策略允许的规范化差异且用户未产生内容编辑
- **THEN** 对账结果为 `unchanged`
- **THEN** 原始 Markdown 继续作为保存结果，不发生无意义重写

#### Scenario: 受支持区域发生安全编辑
- **WHEN** 用户只修改可编辑区域且所有不透明片段完整恢复
- **THEN** 对账结果为 `safe-edit`
- **THEN** 保存候选包含用户修改与逐字节恢复的不透明片段

#### Scenario: 基线或占位不一致
- **WHEN** 原始基线、已验证序列化基线或当前占位登记无法一致对应
- **THEN** 对账结果为 `conflict`
- **THEN** 系统保留原始 Markdown 和当前编辑恢复信息，不得静默选取任一候选覆盖磁盘

#### Scenario: 外部内容变化后重建基线
- **WHEN** 活动文件在 WYSIWYG 会话期间被外部修改并选择重新加载
- **THEN** 旧会话的资格结果、占位登记和对账基线全部失效
- **THEN** 系统必须基于新原文重新执行资格检查后才能再次进入 WYSIWYG

### Requirement: 对账失败提供安全恢复路径
资格拒绝、转换失败或对账冲突时，系统 MUST 保留原始 Markdown，阻止不安全保存，并向用户说明失败阶段与可执行恢复操作。用户 MUST 能切换到 Source 查看和编辑完整原文。

#### Scenario: 保存前对账冲突
- **WHEN** 用户触发保存且对账结果为 `conflict`
- **THEN** 磁盘文件不被不安全候选覆盖
- **THEN** 用户收到包含切换到 Source 操作的明确提示

#### Scenario: Source 恢复不包含内部表示
- **WHEN** 用户从失败或冲突状态进入 Source
- **THEN** Source 显示原始 Markdown 或已明确选择的可恢复候选
- **THEN** 内容不包含占位 token 或内部元数据

#### Scenario: 结构化诊断不泄露正文
- **WHEN** 系统记录资格、转换或对账失败
- **THEN** 日志包含文档会话标识、失败阶段、原因码、位置范围和长度等诊断字段
- **THEN** 默认日志不得记录完整文档正文或不透明片段内容

### Requirement: 新对账路径必须可分阶段启用和回退
系统 MUST 先独立交付只包含 v3 兼容迁移的降风险阶段，并在全部迁移验收证据通过且获得明确批准后，才允许按资格门禁、不透明片段、三方对账的顺序实现完整方案。任一阶段关闭或回退时，Source 模式和原始 Markdown 读取保存能力 MUST 保持可用。

#### Scenario: 仅启用兼容迁移阶段
- **WHEN** 系统仅启用新转换引擎而未启用不透明片段和三方对账
- **THEN** 受支持文档使用新引擎
- **THEN** 不满足安全往返的文档降级到 Source

#### Scenario: 降风险阶段验收未全部通过
- **WHEN** 任一依赖、编译、现有回归、差分语料、磁盘安全、只读文档扫描、交互、性能或回退门禁不是 PASS
- **THEN** 系统不得开始实现或启用资格门禁、不透明片段和三方对账
- **THEN** 失败项必须先修复或回退，并重新执行完整验收矩阵

#### Scenario: 降风险阶段通过后进入完整方案
- **WHEN** 降风险阶段验收报告的全部门禁均为 PASS 且维护者明确批准
- **THEN** 系统可以开始实现资格门禁
- **THEN** 后续仍必须按资格门禁、不透明片段、三方对账的顺序逐级验收

#### Scenario: 回退新 WYSIWYG 路径
- **WHEN** 某阶段出现阻断性回归并被关闭
- **THEN** 系统不再使用该阶段产生的新会话状态
- **THEN** 用户仍可在 Source 模式读取、编辑和保存完整 Markdown
