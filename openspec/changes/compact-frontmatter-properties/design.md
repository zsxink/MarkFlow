# Design

## Context

现有面板通过源码范围补丁维护 Frontmatter，字段输入在 change 时提交，但整体 DOM 重建使焦点、折叠和编辑草稿易丢失。正常属性行还常驻五类操作控件。动机见 proposal.md。

## Goals / Non-Goals

**Goals:** 让属性作为正文上方轻量、紧凑的编辑区；保证菜单、拖放与就地输入在文档切换和只读时都安全；继续复用现有源码补丁与菜单宿主。

**Non-Goals:** 不增加全库属性类型注册，不扩展到任意嵌套 YAML，不引入日期时间类型或新的依赖。

## Decisions

1. 正常属性行使用类型图标、属性名、值与更多按钮四列；采用 UI 无衬线、约 30px 行高、透明输入边框，聚焦时显式显示。属性名列在窄窗口收窄，值列允许换行；新增属性按需展开。保留轻量标题和折叠控制。
2. 输入以明确提交或离开控件时写回，Escape 取消。外部刷新需识别仍在编辑的字段，避免正文更新覆盖草稿；对替换后的目标恢复焦点。上下文菜单每次执行时核对活动文档与只读状态。
3. 类型图标同时作为拖动手柄，避免拖动输入文本引发排序；提供清楚的落点反馈、拖动取消清理以及菜单/键盘替代。复用统一菜单宿主，修正其分隔线与按钮索引映射，供属性菜单安全复用。
4. 结构化操作继续使用 Frontmatter 源码范围补丁。编辑值时保留原键的 YAML 拼写；改名时安全编码新键。数组保持元素类型，删除最后一项时用有效的空数组表示，避免产生不可编辑的空映射。非法日期、数字或异质数组拒绝写入。
5. 组件测试覆盖所有新交互与只读/文档切换；域层测试覆盖引用键、类型和正文原字节保持。浏览器检查三种主题、窄窗口和实际键鼠流程。

## Risks / Trade-offs

- [菜单聚焦导致输入失焦并重渲染] → 提交时保留用户后续目标，并在菜单动作执行时重新解析当前字段。
- [菜单打开后活动文档已改变] → 将菜单绑定到打开时的文档身份，执行前复核，失效即放弃操作。
- [复杂 YAML 被简化] → 不扩大安全子集，保留原文回退及原因；只对可证明安全的源码片段做补丁。
- [手柄拖动不适合键盘用户] → 菜单上/下移与键盘快捷键提供等价行为。

## Migration Plan

无数据迁移，文档格式保持 YAML。回滚 UI 与补丁实现即可恢复旧视图，已保存文档仍可被旧版读取。
