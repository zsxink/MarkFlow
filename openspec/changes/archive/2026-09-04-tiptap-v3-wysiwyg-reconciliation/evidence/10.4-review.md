## Architecture Review

### Bridge as Single Entry Point
All Markdown parse/serialize operations go through `editor.markdown.bridge.ts`:
- `parseMarkdown()` → `editor.markdown.adapter.ts` → TipTap v3 `setContent({ contentType: 'markdown' })`
- `serializeMarkdown()` → `editor.markdown.adapter.ts` → TipTap v3 `getMarkdown()`
- No direct `editor.getMarkdown()` or `editor.setContent(..., { contentType: 'markdown' })` calls outside the adapter.
- No `storage.markdown` access outside adapter comments.

### Admission Pipeline
`classifyEligibility()` → `decideAdmission()` → `verifyAdmission()` / `admitOpaque()`
- `eligible` → parse→serialize→parse→fingerprint verify → `gated` mode
- `eligible-with-opaque` → `admitOpaque()` → render→parse→verify→session → `opaque` mode
- `source-only` → stay Source with stable reason

### Reconcile Pipeline
`reconcileSave()` → `reconcile()` → `unchanged`/`safe-edit`/`conflict`
- Session baselines recorded at admission (8.1)
- Three-way comparison: unchanged (no edit), safe-edit (verified), conflict (corruption)
- Dirty derived only from successful candidate vs persisted baseline

### Opaque Pipeline
`renderOpaque()` → `restoreOpaque()` → `OpaqueRegistry` + session
- Session-local nonce, sentinel namespace collision detection
- Atom nodes hold only slot/category, never raw payload
- Registry cleared on session teardown, pipeline degrade, editor destroy
