# task-list-wysiwyg Specification

## Purpose

定义 MarkFlow 在所见即所得（WYSIWYG）模式下任务列表的视觉与编辑交互契约：复选框尺寸与点击区域、空任务项的插入光标可见性、任务项行间距，以及嵌套与勾选状态下的布局一致性。

## Agent Context

- **源码入口：** `src/styles/editor.css` 的任务列表样式段（`.ProseMirror ul[data-type="taskList"]` 及其子选择器）；`src/editor/init.ts` 注册 `TaskList` 与 `TaskItem.configure({ nested: true })`。
- **关联规范：** `wysiwyg-markdown-round-trip`（任务列表结构与勾选状态往返）、`product-spec.md`（任务列表 P0 支持）、`enter-content-integrity`、`editor-bottom-spacer`。
- **不变量：** 任务列表布局只通过样式实现，不修改 Tiptap 扩展、NodeView 或 Markdown 转换链路；尺寸与间距以 `em` 表达，跟随设置中的正文字号与行高缩放；任务列表样式不得外溢到普通段落、无序列表与有序列表。
- **验证：** `npx vitest run src/__tests__/task-list-styles.test.ts`（样式契约）、`npm run test:e2e`（原生 WebKit 几何实测与截图）、`npx openspec validate task-list-wysiwyg --strict`。

## Requirements

### Requirement: 任务列表复选框尺寸与点击

WYSIWYG 模式下的任务列表复选框 SHALL 具有明确的可视宽高，随正文字号缩放并在 flex 布局中不被压缩；勾选与未勾选状态 SHALL 使用主题强调色，点击复选框 SHALL 切换对应任务项的勾选状态且不移动插入光标。

#### Scenario: 复选框尺寸随正文字号缩放
- **WHEN** 用户在设置中将正文字号从 18px 改为其他可选值
- **THEN** 复选框的可视宽高随字号同比例变化，与同字号正文的视觉比例保持一致
- **THEN** 复选框不因所在行的内容宽度变化而被压缩变形

#### Scenario: 点击复选框切换勾选状态
- **WHEN** 用户点击某个任务项的复选框
- **THEN** 该项勾选状态取反，已勾选与未勾选使用主题强调色区分
- **THEN** 插入光标位置不因点击复选框而跳转到其他位置

### Requirement: 空任务项聚焦后立即可见插入光标

当任务项内容为空时，其内容区 MUST 仍占据可编辑宽度。任务项通过鼠标点击或键盘移动获得焦点后，插入光标 SHALL 立即绘制在内容区内，用户无需先输入字符即可继续输入、移动光标或删除内容。

#### Scenario: 点击空任务项出现光标
- **WHEN** 文档中某个任务项没有任何文本，用户用鼠标点击该任务项的空白内容区
- **THEN** 插入光标立即出现在该任务项内容区的起始位置
- **THEN** 用户直接输入的字符出现在该任务项中

#### Scenario: 键盘移动到空任务项出现光标
- **WHEN** 用户用键盘把光标移动到空任务项
- **THEN** 插入光标立即可见，无需先输入字符
- **THEN** 继续输入、左右移动光标和退格删除均在该任务项内正常生效

#### Scenario: 空任务项内容区宽度可测量
- **WHEN** 任务项内容为空且编辑器已渲染
- **THEN** 该任务项内容区的可编辑宽度大于零，且不小于该行可用宽度减去复选框与间距后的剩余宽度

### Requirement: 任务项行间距小于段落间距

同一任务列表中连续任务项之间的垂直间距 MUST 明显小于普通段落之间的间距。任务项内部多段文本 SHALL 保持清晰可读的行距，且不得因叠加段落下边距与列表项下边距而产生额外留白。

#### Scenario: 连续任务项间距小于段落间距
- **WHEN** 文档中同时存在连续多个任务项和连续多个普通段落
- **THEN** 相邻任务项之间的垂直间距小于相邻段落之间的垂直间距

#### Scenario: 多行任务项文本保持可读
- **WHEN** 单个任务项包含多段文本或因换行折行而占多行
- **THEN** 该任务项内部的行距与段落行距保持可读，不出现行与行重叠或过度压缩

### Requirement: 任务列表布局状态一致性

任务列表布局 SHALL 在嵌套任务列表、空项与非空项、已勾选与未勾选状态下保持一致，且 MUST NOT 改变任务列表以外的段落、无序列表与有序列表样式。

#### Scenario: 嵌套任务列表布局一致
- **WHEN** 任务项中包含嵌套任务列表
- **THEN** 嵌套层级的复选框尺寸、内容区宽度与行间距与顶层任务项保持一致
- **THEN** 嵌套结构不因布局规则而改变缩进或层级关系

#### Scenario: 混合状态布局一致
- **WHEN** 同一任务列表同时包含空项、非空项、已勾选项和未勾选项
- **THEN** 各项的复选框对齐位置与内容区起始位置保持一致，不出现基线错位

#### Scenario: 任务列表样式不外溢
- **WHEN** 文档同时包含任务列表、普通段落、无序列表与有序列表
- **THEN** 普通段落与普通列表的间距、缩进和标记样式保持原有表现

### Requirement: 已勾选任务项正文的视觉弱化

所见即所得模式下，已勾选任务项（勾选状态为 true 的 `li`）的正文颜色 SHALL 使用淡于未勾选项正文颜色的主题前景色 token（如 `var(--muted)`），未勾选项 SHALL 保持当前正文颜色（`var(--fg)`）。该弱化 SHALL 仅作用于任务项正文，MUST NOT 硬编码具体颜色值，SHALL 在亮色与暗色主题下均正确呈现。用户将光标移入已勾选任务项编辑或选中其文本时，文本 SHALL 保持可读。勾选状态切换时正文颜色 SHALL 随 `data-checked` 属性即时变化，无需重新打开文档。源码模式（CodeMirror）的任务列表文本颜色 SHALL 不受影响。

#### Scenario: 勾选后正文颜色变淡
- **WHEN** 同一任务列表中同时存在已勾选与未勾选任务项
- **THEN** 已勾选项正文颜色明显淡于未勾选项，两者形成清晰视觉层次

#### Scenario: 勾选状态切换即时生效
- **WHEN** 用户点击某个未勾选任务项的复选框使其变为已勾选
- **THEN** 该项正文颜色立即变淡，无需重新打开文档或手动刷新

#### Scenario: 已勾选项内编辑仍可读
- **WHEN** 用户把光标移入已勾选任务项并选中文本
- **THEN** 文本与选区保持可读，弱化颜色不阻碍编辑

#### Scenario: 明暗主题兼容
- **WHEN** 用户在亮色与暗色主题间切换
- **THEN** 已勾选与未勾选任务项的颜色区分在两种主题下均正确

#### Scenario: 源码模式不受影响
- **WHEN** 用户切换到源码模式查看同一任务列表
- **THEN** 源码模式下 `- [x]` 与 `- [ ]` 文本颜色不因本弱化规则改变

### Requirement: 任务列表结构与勾选状态往返保真

任务列表的布局调整 MUST NOT 影响 Markdown 解析与序列化。文档经导入、编辑、保存后，任务列表的条目顺序、嵌套层级与勾选状态 SHALL 保持不变。

#### Scenario: 保存后勾选状态保持
- **WHEN** 用户在 WYSIWYG 中切换某个任务项的勾选状态并保存文件
- **THEN** 磁盘上的 Markdown 中该项的 `- [x]` / `- [ ]` 标记与界面一致
- **THEN** 重新打开该文件后任务列表结构与勾选状态与保存时一致
