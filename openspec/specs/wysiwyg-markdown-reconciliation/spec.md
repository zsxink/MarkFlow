# wysiwyg-markdown-reconciliation Specification

## Purpose
定义原始 Markdown、WYSIWYG 文档和序列化结果之间的安全对账协议，使不完全受支持的语法可被保留，并在无法证明安全时阻止静默覆盖。

## Requirements

### Requirement: WYSIWYG 资格门禁

系统 MUST 在加载 Markdown 到可编辑 WYSIWYG 前完成语义安全往返检查。检查发现无法安全往返的块时，系统 MUST 先尝试局部字面量保留并获得无损证明；无法证明无损时返回稳定原因并避免创建可能覆盖原文的可编辑会话。WYSIWYG 文档大小和最大行数阈值只影响自动打开模式，不得作为手动切换的拒绝条件。系统 MUST NOT 依据节点数、块级结构数量或其他复杂度预算拒绝 WYSIWYG 加载。

#### Scenario: 完全受支持的文档
- **WHEN** 文档只包含往返规范承诺支持的语法且解析成功
- **THEN** 资格结果为 `eligible`，文档可进入可编辑 WYSIWYG

#### Scenario: 可透传的不透明片段
- **WHEN** 文档包含 WYSIWYG 不原生理解但边界可确定且可原样恢复的片段
- **THEN** 资格结果为 `eligible-with-opaque` 并列出片段位置和类别

#### Scenario: 无法安全往返的文档
- **WHEN** 文档中的块无法通过往返语义校验
- **THEN** 系统先尝试局部字面量保留；不能证明无损时返回 `source-only` 和稳定原因
- **THEN** 系统不得创建可能覆盖原文的可编辑 WYSIWYG 会话

#### Scenario: 代码字面量不参与不支持语法扫描

- **WHEN** 围栏代码块或行内代码包含类似 HTML、数学公式、脚注或引用链接的字面量
- **THEN** 资格检查不得把代码字面量识别为不支持的正文语法
- **THEN** 文档仍须经过正常的语义往返校验后才能进入 WYSIWYG


#### Scenario: 列数不一致的 GFM 表格

- **WHEN** GFM 表格的表头、分隔行或数据行列数不一致且转换器可能丢弃单元格
- **THEN** 系统 MUST 将该畸形表格整块保留为局部字面量块，并保持其字面内容不变
- **THEN** 文档其余部分仍可编辑，且本地化往返校验通过后方可进入 WYSIWYG
- **THEN** 若该表格无法被局部保留证明，则资格结果为 `source-only` 并包含稳定的畸形表格原因


#### Scenario: 超出大小上限的文档
- **WHEN** 文档超过用户配置的 WYSIWYG 文件大小阈值，但 Markdown 内容通过完整安全资格检查
- **THEN** 大小超限只使文档默认以源码模式打开，不会单独返回 `source-only`
- **THEN** 用户主动切换后完整内容进入 WYSIWYG 渲染

#### Scenario: 超过自动模式阈值但安全可渲染
- **WHEN** 文档超过用户配置的 WYSIWYG 大小阈值，但 Markdown 内容通过完整安全资格检查
- **THEN** 资格结果仍为 `eligible` 或 `eligible-with-opaque`
- **THEN** 用户手动切换后，完整内容进入 WYSIWYG 渲染

#### Scenario: 节点数不作为 WYSIWYG 门禁
- **WHEN** 文档的节点数或块级结构数量较多，但内容能够通过正常的 Markdown 安全往返检查
- **THEN** 系统允许进入 WYSIWYG，不以结构数量作为拒绝原因

#### Scenario: 结构过于复杂的文档
- **WHEN** 文档包含大量块级结构，但内容能够通过正常的 Markdown 安全往返检查
- **THEN** 文档仍可进入 WYSIWYG，不计算或应用结构复杂度拒绝预算

### Requirement: 不透明片段必须可逆透传
系统 MUST 为每个不透明片段生成与用户文本不可碰撞的会话级标识，并在 WYSIWYG 表示中保留不可编辑的占位节点。序列化时 MUST 按原始顺序逐字节恢复片段，且内部 token、标识和元数据不得写入磁盘、剪贴板或导出内容。

#### Scenario: 不透明片段原样恢复
- **WHEN** 用户只编辑不透明片段之外的受支持内容
- **THEN** 序列化结果在对应位置逐字节恢复每个原始不透明片段
- **THEN** 受支持区域的编辑正常保留

#### Scenario: 多个相同片段不串位
- **WHEN** 文档包含内容相同但位置不同的多个不透明片段
- **THEN** 每个片段拥有不同的会话级标识
- **THEN** 序列化按各自原始位置和内容恢复，不得互换、合并或去重

#### Scenario: 占位完整性被破坏
- **WHEN** 占位节点被删除、复制、重复、改写或无法与登记表一一对应
- **THEN** 恢复失败并进入冲突状态
- **THEN** 系统不得输出包含内部 token 的 Markdown

### Requirement: 三方对账必须区分安全结果与冲突
系统 MUST 在模式切换和保存边界，以会话原始 Markdown、上一次已验证的 WYSIWYG 序列化基线和当前序列化候选执行对账。对账 MUST 返回 `unchanged`、`safe-edit` 或 `conflict`，并只允许前两种结果进入正常保存。

#### Scenario: 无用户编辑的等价格式差异
- **WHEN** 当前候选仅包含兼容策略允许的规范化差异且用户未产生内容编辑
- **THEN** 对账结果为 `unchanged`
- **THEN** 原始 Markdown 继续作为保存结果，不发生无意义重写

#### Scenario: 受支持区域发生安全编辑
- **WHEN** 用户只修改可编辑区域且所有不透明片段完整恢复
- **THEN** 对账结果为 `safe-edit`
- **THEN** 保存候选包含用户修改与逐字节恢复的不透明片段

#### Scenario: 基线或占位不一致
- **WHEN** 原始基线、已验证序列化基线或当前占位登记无法一致对应
- **THEN** 对账结果为 `conflict`
- **THEN** 系统保留原始 Markdown 和当前编辑恢复信息，不得静默选取任一候选覆盖磁盘

#### Scenario: 外部内容变化后重建基线
- **WHEN** 活动文件在 WYSIWYG 会话期间被外部修改并选择重新加载
- **THEN** 旧会话的资格结果、占位登记和对账基线全部失效
- **THEN** 系统必须基于新原文重新执行资格检查后才能再次进入 WYSIWYG

### Requirement: 对账失败提供安全恢复路径
只有在无法证明安全候选时（例如对账冲突、本地化往返校验失败或占位完整性被破坏），系统 MUST 保留原始 Markdown，阻止不安全保存，并向用户说明失败阶段与可执行恢复操作。通过本地化往返证明的文档 MAY 保存其已验证候选，但该候选 MUST 只包含经证明无损的内容。用户 MUST 能切换到 Source 查看和编辑完整原文。

#### Scenario: 保存前对账冲突
- **WHEN** 用户触发保存且对账结果为 `conflict`
- **THEN** 磁盘文件不被不安全候选覆盖
- **THEN** 用户收到包含切换到 Source 操作的明确提示

#### Scenario: 局部保留会话的安全保存
- **WHEN** 会话通过局部字面量保留准入，且保存候选能重新解析为编辑器当前语义
- **THEN** 系统 MAY 写入该候选，其中局部保留块逐字节保持原文
- **THEN** 系统 MUST NOT 写入任何内部标记、占位 token 或会话元数据

#### Scenario: 保存证明取自候选本身
- **WHEN** 局部保留会话生成保存候选
- **THEN** 证明 MUST 基于将要写入的候选字节，而非仅基于中间标记形式
- **THEN** 若还原字面量块时留下渲染器生成的分隔换行，使该块在重新打开时被吞并或膨胀，结果 MUST 为 `conflict` 并阻止写入

#### Scenario: 局部保留证明失败
- **WHEN** 局部保留块无法与源文一一对应，或其候选无法重新解析为当前语义
- **THEN** 系统 MUST 阻止保存并保留原始 Markdown
- **THEN** Source 模式仍提供完整原文

#### Scenario: Source 恢复不包含内部表示
- **WHEN** 用户从失败或冲突状态进入 Source
- **THEN** Source 显示原始 Markdown 或已明确选择的可恢复候选
- **THEN** 内容不包含占位 token 或内部元数据

#### Scenario: 结构化诊断不泄露正文
- **WHEN** 系统记录资格、转换或对账失败
- **THEN** 日志包含文档会话标识、失败阶段、原因码、位置范围和长度等诊断字段
- **THEN** 默认日志不得记录完整文档正文或不透明片段内容

### Requirement: 无法安全往返的块局部字面量保留
系统 MUST 支持把无法安全往返的完整 Markdown 块保留为可编辑的局部字面量块，使文档其余受支持内容保持正常 WYSIWYG 编辑。字面量块 MUST 逐字节保留原文（含 CRLF 等作者字符），MUST 在编辑器中可见并可局部编辑，且 MUST NOT 把 HTML 等原文当作可执行内容渲染。字面量块 MUST NOT 消耗或吞并相邻的受支持内容，也不得与围栏代码中的同字面量混淆。字面量块的呈现 MUST 与源码模式观感一致：不呈现代码框外观（无背景色框、无边框、无额外 padding），以等宽字体展示原文。字面量块 MUST 支持单击直接编辑（无需双击等额外门槛）；编辑器只读时 MUST 禁止编辑。

#### Scenario: 局部保留后其余内容可编辑
- **WHEN** 文档包含一个无法安全往返的块，且其前后的内容都受支持
- **THEN** 该块以局部字面量块呈现，原文逐字节不变
- **THEN** 其余标题、列表、表格与代码块仍作为各自的结构正常渲染和编辑

#### Scenario: 局部字面量块可局部编辑
- **WHEN** 用户编辑某个局部字面量块的文本
- **THEN** 只有该块的原文被更新，其余块内容不受影响
- **THEN** 该编辑后的内容仍须通过保存前的往返证明才可写入

#### Scenario: 局部保留块观感与源码模式一致
- **WHEN** 一个无法安全往返的块以局部字面量形式呈现在 WYSIWYG 中
- **THEN** 该块显示为无背景框、无边框、无额外 padding 的等宽字体原文
- **THEN** 该块不得呈现与围栏代码块相同的视觉外观

#### Scenario: 单击直接编辑
- **WHEN** 编辑器可编辑且用户单击一个局部字面量块
- **THEN** 用户可以直接修改该块文本，无需双击等额外交互
- **WHEN** 编辑器处于只读模式
- **THEN** 局部字面量块不可编辑

#### Scenario: 局部保留不破坏作者字符
- **WHEN** 原文在局部保留块中使用 CRLF 行尾或引用式定义等标记
- **THEN** 序列化结果 MUST 逐字节保留这些作者字符
- **THEN** 行尾不得被归一化为 LF，Marked 词法分析省略的引用式定义也不得丢失

#### Scenario: 内部标记不落盘
- **WHEN** 系统为局部保留块生成用于隔离与证明的临时标记
- **THEN** 标记 MUST 在保存、导出与剪贴板内容中完全消失
- **THEN** 若标记无法被证明完整还原，系统 MUST 阻止写入该候选

### Requirement: 字面量块语法合法后自动升级
系统 MUST 在局部字面量块的编辑停顿后（输入法组合结束后经短暂防抖），对该块当前原文执行单块安全往返校验（资格判定、解析、序列化、再解析与语义指纹比对）。校验通过时，系统 MUST 在单个编辑事务内把该字面量原子节点替换为解析得到的真实 WYSIWYG 块（可能为多个节点），使撤销为一步完整操作；校验不通过时 MUST 保持原文呈现且不打扰用户。升级后的真实块按普通 WYSIWYG 块参与后续编辑与保存对账，保存证明链 MUST 对全部升级后的文档继续成立。

#### Scenario: 畸形表格修复后自动升级
- **WHEN** 用户把一个因列数不一致而保留的表格原文编辑为合法表格并在停顿后触发校验
- **THEN** 该字面量块在单个事务内被替换为真实表格节点，可直接交互
- **THEN** 撤销（undo）可一步回到字面量原子节点形态，且该节点仍可继续直接编辑

#### Scenario: 语法仍不合法时保持原文
- **WHEN** 字面量块的编辑停顿后单块校验未通过（内容仍无法安全往返）
- **THEN** 该块保持原文呈现，不弹出提示、不丢失用户输入

#### Scenario: 输入法组合期间不触发升级
- **WHEN** 用户正在使用输入法组合输入（composition 进行中）
- **THEN** 不触发单块校验与升级，避免打断输入

#### Scenario: 升级后保存证明仍成立
- **WHEN** 文档中全部字面量块均已升级为真实块后被保存
- **THEN** 保存对账继续按既有协议分类（unchanged/safe-edit/conflict），升级本身不得引入冲突

### Requirement: 新对账路径必须可分阶段启用和回退
系统 MUST 先独立交付只包含 v3 兼容迁移的降风险阶段，并在全部迁移验收证据通过且获得明确批准后，才允许按资格门禁、不透明片段、三方对账的顺序实现完整方案。任一阶段关闭或回退时，Source 模式和原始 Markdown 读取保存能力 MUST 保持可用。

#### Scenario: 仅启用兼容迁移阶段
- **WHEN** 系统仅启用新转换引擎而未启用不透明片段和三方对账
- **THEN** 受支持文档使用新引擎
- **THEN** 不满足安全往返的文档降级到 Source

#### Scenario: 降风险阶段验收未全部通过
- **WHEN** 任一依赖、编译、现有回归、差分语料、磁盘安全、只读文档扫描、交互、性能或回退门禁不是 PASS
- **THEN** 系统不得开始实现或启用资格门禁、不透明片段和三方对账
- **THEN** 失败项必须先修复或回退，并重新执行完整验收矩阵

#### Scenario: 降风险阶段通过后进入完整方案
- **WHEN** 降风险阶段验收报告的全部门禁均为 PASS 且维护者明确批准
- **THEN** 系统可以开始实现资格门禁
- **THEN** 后续仍必须按资格门禁、不透明片段、三方对账的顺序逐级验收

#### Scenario: 回退新 WYSIWYG 路径
- **WHEN** 某阶段出现阻断性回归并被关闭
- **THEN** 系统不再使用该阶段产生的新会话状态
- **THEN** 用户仍可在 Source 模式读取、编辑和保存完整 Markdown
