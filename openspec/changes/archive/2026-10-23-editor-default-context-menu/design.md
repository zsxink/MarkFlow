# Design

## Context

当前 `main.ts` 在 document 冒泡阶段统一阻止原生菜单，表格、图片、图表和文件树在更近的事件处理器中展示专用菜单。WYSIWYG 使用 Tiptap，源码使用 CodeMirror 6；菜单工厂负责全局单例、焦点和关闭。

## Goals / Non-Goals

**Goals:** 让未被专用菜单拦截的编辑区域拥有模式感知的编辑菜单，并统一菜单外观和分层操作。

**Non-Goals:** 改变图片、图表导出行为或重做各专用菜单的命令内容；引入新依赖；改变浏览器原生右键菜单策略。

## Decisions

- 保留 document 级右键分流：目标在侧栏时维持其既有菜单；目标在图片/图表/表格等专用处理区域时由现有处理器停止冒泡；其余目标显示默认菜单。文本输入控件展示剪切/复制/粘贴/全选。
- 新建编辑器菜单模块，按当前模式读取 Tiptap/CodeMirror 选区；命令执行时使用统一编辑器 API。右键落在新位置时移动光标，右键落在当前非折叠选区内时保留该选区。
- 扩展统一菜单项以支持快捷键文案与子菜单数据；由同一工厂渲染和委托处理子菜单，保留现有 `onClick` 调用方接口。
- 通过共享 CSS 统一菜单视觉。菜单主面板和子面板均实测尺寸后贴合光标，并在空间不足时翻转方向。

## Risks / Trade-offs

- 异步读取剪贴板可能被系统权限拒绝 → 通过现有 toast 通知用户，其他菜单操作仍可用。
- 菜单子项多时可能超出窗口 → 限制主面板和子面板高度，允许滚动并在边缘翻转。
- 浏览器右键目标可能位于自定义控件 → document 分流保持在冒泡阶段，并优先尊重已调用 `stopPropagation()` 的专用处理器。
