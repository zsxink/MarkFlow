# Spec Delta

## MODIFIED Requirements

### Requirement: 设置面板文档上限分组与持久化

系统 MUST 在设置面板提供「文档大小/行数上限」分组，包含以下三项可配置项，字段值 MUST 来自当前设置，保存后 MUST 持久化到 `settings.json` 并在重启后保持：

- 所见即所得文档大小（数字框 + KB/MB 单位选择，默认 1MB）；
- 源码文档大小（数字框 + KB/MB 单位选择，默认 10MB）；
- 最大行数（数字框，默认 100 万）。

持久化层 MUST 保证设置字段在 TS 与 Rust 两侧结构体中同步声明，使后端任何「读取-修改-保存」往返不丢弃这些字段；旧配置文件中的已删除字段 MUST 被静默忽略并在下次保存时剥离，MUST NOT 触发版本迁移或报错。

#### Scenario: 分组显示当前值并持久化

- **WHEN** 用户打开设置面板的文档上限分组
- **THEN** 三个字段显示当前设置值（两个体积字段带 KB/MB 单位，按存储字节换算为所选单位的数值展示）
- **WHEN** 用户修改为合法值并保存
- **THEN** 值按所选单位换算为字节持久化到 `settings.json`，重启应用后保持

#### Scenario: 设置往返不丢失字段

- **WHEN** 用户保存文档上限设置后，后端执行任何会读取并回写设置的操作（如记录最近文件）
- **THEN** 三个字段的值不被丢弃或重置为默认

#### Scenario: 旧配置残留字段被剥离

- **WHEN** settings.json 中仍含有精简前已删除的旧上限字段（如 `wysiwygAdmissionBytes`）
- **THEN** 设置加载正常回落新字段默认值，不报错
- **THEN** 下一次保存后旧字段从 settings.json 中消失

## ADDED Requirements

### Requirement: 档位判定与准入分类从三项设置读取阈值

档位判定与所见即所得准入分类 MUST 从同一份用户设置读取阈值（所见即所得文档大小、源码文档大小、最大行数）；设置缺失或非法时 MUST 回落默认值（所见即所得 1MB、源码 10MB、最大行数 100 万）。阈值修改 MUST 对新打开的文档立即生效，无需重启；已打开的文档 MUST NOT 受影响。阈值计算函数 MUST 保持纯函数性质，通过参数注入配置，不直接依赖状态存储。

编辑器复杂度限制链路（节点数/文本长度上限）MUST 移除：其超限标志无任何下游消费者，超限仅产生一条与实际行为不符的提示，不再提供节点数/文本长度上限设置。

#### Scenario: 档位判定使用自定义配置

- **WHEN** 用户把所见即所得文档大小设为 512KB 后打开一个 800KB 的文档
- **THEN** 该文档按大文件（Large）档位处理，显示降级条建议源码模式

#### Scenario: 准入分类使用自定义阈值

- **WHEN** 用户把所见即所得文档大小从 1MB 提高到 2MB 后打开一个 1.5MB 的文档
- **THEN** 该文档被判定可进入所见即所得，不再因体积被拒

#### Scenario: 设置缺失时回落默认值

- **WHEN** 设置中未包含某阈值字段（如旧配置文件升级后）
- **THEN** 对应链路使用默认值（1MB/10MB/100 万行），行为不突变

### Requirement: 文档上限输入校验与错误回显

文档上限输入的校验规则：

- 恒定规则：所有数值必须大于 0。
- 排序规则：所见即所得文档大小 MUST NOT 超过源码文档大小。

非法输入 MUST 在分组内回显明确错误并拒绝保存该值；恢复合法后错误消失且可正常保存。默认组合（1MB ≤ 10MB）天然满足排序规则，MUST NOT 存在依赖存量豁免的特例路径。

#### Scenario: 非法输入回显错误且不写入

- **WHEN** 用户把所见即所得文档大小改为大于源码文档大小的值
- **THEN** 分组内显示错误提示，该非法值不被保存，生效阈值保持最近一次合法值

#### Scenario: 非正数被拒绝

- **WHEN** 用户在任一数值字段输入 0 或负数
- **THEN** 分组内显示错误提示，该值不被保存

#### Scenario: 恢复合法后可正常保存

- **WHEN** 用户修正非法输入为合法值
- **THEN** 错误提示消失，新值正常保存并生效

### Requirement: 超限提示引用实际生效上限

因超过阈值而向用户展示的提示文案 MUST 引用实际生效的配置数值，不得引用与配置脱节的硬编码常量。

#### Scenario: 准入拒绝提示包含配置上限

- **WHEN** 文档因体积超过所见即所得文档大小被保留在源码模式，且用户已把该上限设为 2MB
- **THEN** 提示文案包含文档实际体积与 2MB 这一实际生效上限

## REMOVED Requirements

### Requirement: 各链路统一从设置读取阈值并对新打开文档立即生效

**Reason**: 8 项设置精简为 3 项后，默认值从「256KB/10,000 行准入、10,000 节点/500,000 字符、1MB/10MB/5,000/50,000 行档位」变为「所见即所得 1MB、源码 10MB、最大行数 100 万」，且编辑器复杂度限制链路（节点数/文本长度上限）整体移除——其超限标志无任何下游消费者，超限仅产生一条与实际行为不符的提示，且每事务全量统计本身就是编辑性能负担。

**Migration**: 由 ADDED requirement「档位判定与准入分类从三项设置读取阈值」取代；档位判定与准入分类两条链路继续存在并改读新字段，原「复杂度限制使用自定义上限」场景随复杂度链路一起消失。

### Requirement: 输入校验与错误回显

**Reason**: 旧排序规则（large<huge、准入≤large 等 4 条）与「存量默认组合豁免」机制全部绑定被删除字段；新 3 项只有一条排序约束（所见即所得 ≤ 源码），且新默认组合天然合法，豁免机制无存在基础。

**Migration**: 由 ADDED requirement「文档上限输入校验与错误回显」取代；「存量默认组合不阻塞保存」场景随豁免机制一起移除，其余场景语义延续。

### Requirement: 超限提示引用实际生效数值

**Reason**: 复杂度限制链路移除后，本 requirement 仅剩准入拒绝一个有效场景。

**Migration**: 由 ADDED requirement「超限提示引用实际生效上限」取代；准入拒绝提示继续引用实际生效的所见即所得文档大小。
