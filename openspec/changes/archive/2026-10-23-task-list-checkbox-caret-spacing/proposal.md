# Proposal

## Why

所见即所得编辑器里的任务列表有三个同时暴露的显示缺陷：复选框沿用浏览器默认尺寸，与 18px 正文比例不协调；空任务项获得焦点时看不到插入光标，必须输入第一个字符后光标才出现；任务项之间的垂直间距大于普通段落间距。三者共同让任务列表成为编辑器里唯一"看起来没写完"的块级结构，也直接违反 Markdown 任务列表 P0 的可用性预期。

## What Changes

- 任务列表复选框获得明确的可视尺寸与不可压缩约束，尺寸随正文字号缩放，并与主题强调色保持一致。
- 任务项内容区在空内容时仍占据可编辑宽度，使空任务项点击或键盘聚焦后立即绘制插入光标。
- 任务项内部段落的默认下边距被任务列表范围内覆盖，任务项之间改用更小的独立间距，保证连续任务项的行距明显小于普通段落间距。
- 嵌套任务列表、复选框点击切换、编辑区点击定位、主题配色与常规段落/列表样式保持现有行为。

## Capabilities

### New Capabilities

- `task-list-wysiwyg`: 所见即所得模式下任务列表的视觉与交互契约——复选框尺寸与点击、空任务项光标可见性、任务项行间距，以及嵌套与勾选状态的布局一致性。

### Modified Capabilities

无。

## Impact

- `src/styles/editor.css` 中的任务列表样式段（`.ProseMirror ul[data-type="taskList"]` 及其子选择器）。
- 可能新增针对任务列表布局的样式契约回归测试与原生 e2e 场景（空任务项光标、复选框尺寸、任务项间距）。
- 不涉及 Markdown 解析/序列化、Tiptap 扩展配置、Rust 侧或持久化格式；导入导出结构与勾选状态由既有 `wysiwyg-markdown-round-trip` 契约继续保证。
