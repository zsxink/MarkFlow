# paragraph-block-prefix-escape Specification

## Purpose
定义以「被转义的行首块级前缀」开头的合法段落的序列化保真，确保这类段落从源码进入 WYSIWYG 时不因序列化丢失反斜杠而触发往返校验误拦截，且真实块级结构不受影响。

## Requirements

### Requirement: 段首被转义块级前缀往返保真
对以被转义块级前缀开头的独立段落（如 `6\. 正文`、`\- foo`、`\# foo`、`\---`、`\> foo`、`\` `` `` `foo`、`\<div> foo`），系统 MUST 在序列化时对该段落内每一行的行首补回反斜杠转义（段落含软换行时包括全部续行，而非仅首行），使序列化结果再次解析时仍为普通段落而非被当作有序列表、无序列表、标题、分隔线、块引用、围栏代码块或 HTML 块。Setext 下划线整行（如 `===`）MUST 仅在段落非首行时补转义（首行 `===` 是普通文本）。文档经历 Markdown → WYSIWYG → Markdown 往返后 MUST 保留文本内容与段落语义。

#### Scenario: 字面有序列表标记的段落可进入 WYSIWYG
- **WHEN** 文档包含以被转义的「数字句点」开头的独立段落，如 `6\. 这是一段以转义数字开头的正文`、`1\. 另一段`、`10\. 第三段`
- **THEN** 序列化输出保留反斜杠（`6\. 正文`），再次解析仍为同一普通段落
- **THEN** 往返校验通过，文档可进入可编辑 WYSIWYG，编辑保存后语义不变

#### Scenario: 数字后带点或括号的多种空白均保真
- **WHEN** 段首为 `数字.` 或 `数字)` 且后随空格、制表符或行尾，如 `6\.  正文`、`6\.\t正文`、`5\) 正文`、长数字 `999999999\. x`
- **THEN** 序列化将行首 `数字[.)]` 补为 `数字\[.)]`，再次解析仍为普通段落
- **THEN** 往返校验通过

#### Scenario: 被转义的无序列表标记段落保真
- **WHEN** 文档包含以被转义的 `-` 或 `+` 开头且后随空白的段落，如 `\- foo`、`\+ foo`
- **THEN** 序列化补回反斜杠（`\- foo`、`\+ foo`），再次解析仍为普通段落而非列表项
- **THEN** 往返校验通过

#### Scenario: 被转义的 ATX 标题标记段落保真
- **WHEN** 文档包含以被转义的 `#`-`######` 开头且后随空白的段落，如 `\# foo`、`\### foo`
- **THEN** 序列化补回反斜杠，再次解析仍为普通段落而非标题
- **THEN** 往返校验通过

#### Scenario: 被转义的分隔线/Setext 下划线整行保真
- **WHEN** 文档的单个段落以字面分隔线标记组成，如 `\---`、`\***`、`\___`（允许尾随空白）
- **THEN** 序列化补回反斜杠，再次解析仍为普通段落而非分隔线或 Setext 下划线
- **THEN** 往返校验通过

#### Scenario: 软换行续行的块级前缀同样补转义
- **WHEN** WYSIWYG 中一个含软换行的段落，其第二行以字面块级前缀开头（如 `正文第一行\n1. 看起来像列表`、`正文\n# 看起来像标题`、`正文\n- 看起来像条目`、`正文\n---`）
- **THEN** 序列化对每个续行行首补回反斜杠（`1\.`、`\#`、`\-`、`\---`），再次解析仍为同一个多行普通段落
- **THEN** 往返校验通过，续行不被解析为列表、标题或分隔线

#### Scenario: 块引用前缀续行不拆块
- **WHEN** WYSIWYG 中一个含软换行（或两空格硬换行）的段落，其续行以 `>` 开头（如 `正文\n> 看起来像引用`、`正文\n>foo` 无空格形态）
- **THEN** 序列化输出使续行不再构成块引用起始（行首 `>` 经上游文本编码为 `&gt;`，`escapeParagraphMarkdown` 另行保证 `\>` 兜底），再次解析仍为同一个多行普通段落
- **THEN** 往返校验通过，续行不被解析为 blockquote

#### Scenario: 围栏开头续行不拆块
- **WHEN** WYSIWYG 中一个含软换行的段落，其续行以三个及以上反引号或波浪线开头（如 `正文\n``` 看起来像代码`、`正文\n~~~`）
- **THEN** 序列化输出使续行不再构成围栏开始（行首反引号/波浪线经上游逐字符转义，`escapeParagraphMarkdown` 另行保证 `\` 转义兜底），再次解析仍为同一个多行普通段落
- **THEN** 往返校验通过，续行不拆为 fenced code block、后续行不被围栏吞掉

#### Scenario: Setext 下划线续行补转义
- **WHEN** WYSIWYG 中一个含软换行的段落，其非首行是整行 `===`（如 `正文\n===`）
- **THEN** 序列化对续行行首补转义（`\===`），再次解析仍为同一个多行普通段落，上一行不升级为 H1 标题
- **WHEN** 段落首行是 `===`（普通文本，无前导行）
- **THEN** 序列化不对其补转义，首行拼写保持 `===`，再次解析仍为普通段落

#### Scenario: HTML 块起始形态续行不拆块
- **WHEN** WYSIWYG 中一个含软换行的段落，其续行以 `<div>`、`<!--`、`<script>` 等 HTML 块起始形态开头（如 `正文\n<div>看起来像 HTML`）
- **THEN** 序列化输出使续行不再构成 HTML 块开始（行首 `<` 经上游文本编码为 `&lt;`，`escapeParagraphMarkdown` 另行保证 `\<` 兜底），再次解析仍为同一个多行普通段落
- **THEN** 往返校验通过，续行走普通段落路径而非 opaque html-block 识别

#### Scenario: 以被转义块引用/围栏/HTML 开头的段落首行保真
- **WHEN** 文档包含以被转义形态开头的独立段落，如 `\> foo`、`\`\`\` foo`、`\<div> foo`
- **THEN** 序列化输出再次解析仍为普通段落而非 blockquote、围栏代码块或 HTML 块（行首不再构成原生块起始；拼写由上游文本编码决定，如 `&gt; foo`）
- **THEN** 往返校验通过

### Requirement: 真实块级结构不受段落转义影响
转义仅应用于普通段落节点的序列化。真实的有序列表、无序列表、任务列表、引用、标题（ATX/Setext）、分隔线、围栏代码块、表格及嵌套结构 MUST 保持既有序列化输出不变，不得被段落转义逻辑改写。

#### Scenario: 真实块级节点输出不变
- **WHEN** 文档包含真实的有序列表 `1. a\n2. b`、无序列表 `- a\n- b`、任务列表 `- [ ] a`、引用 `> quote`、标题 `# hi`、分隔线 `---`、嵌套列表 `- a\n  - b`、强调 `***bold***`、Setext `foo\n---`
- **THEN** 这些结构仍按各自节点渲染器输出相同的 Markdown
- **THEN** 段落转义逻辑不对这些输出做任何改写，往返校验通过

#### Scenario: 段首平凡文本不受额外转义
- **WHEN** 段落首行为普通文本或非块级歧义内容，如 `-foo`（横杠不后随空白）、`6.x`（数字点后无空白）、`a 6. x`（数字点非行首）、`hello **world**`
- **THEN** 序列化输出不新增转义，保持原样，往返校验通过
